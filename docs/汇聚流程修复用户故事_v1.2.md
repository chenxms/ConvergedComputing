- 文档类型：用户故事（PM）
- 版本：v1.2

- 涉及模块：subjects_builder、subjects_v12_api、calculation_service、repositories
- 作者：PM（基于现网实现审计与技术分析）
- 目的：为 DEV 提供一次性、可验收的修复需求，稳定 v1.2 汇聚出数口径与结构

## 背景与问题陈述

当前 v1.2 汇聚流程已具备统一结构与主要指标，但存在若干逻辑与口径问题，影响“学校页统计正确性”“问卷分布口径正确性”和“区域/学校一致性”。本故事旨在以最小变更集修复关键缺陷，并补齐一致性要求与可验证验收标准。

关键现状问题（摘自代码与运行逻辑核对）：
- 问题1（P0）：问卷“维度→题目选项分布”跨科目混算。
  - 位置：`app/services/subjects_builder.py::_compute_questionnaire_dimension_question_option_distribution`
  - 现状：SQL 仅按 `batch_code` 过滤，未限定 `subject_name`（qqd/qdm 均需），导致同批次不同问卷科目混入。
- 问题2（P0）：学校页增强统计（百分位、区分度、等级分布）误用“区域级”数据源。
  - 位置：`app/api/subjects_v12_api.py::_fetch_v12_school`
  - 现状：通过 `_fetch_student_scores(batch_code)`（全区域）计算增强统计，再注入学校页，口径错位。
- 问题3（P1）：`list_subjects` 可能包含 `interaction` 类型，但下游 SQL 普遍限定 `IN ('exam','questionnaire')`，造成不一致。
- 风险1（P1）：区域维度均分未 JOIN 主数据 `school_master_data.status='ACTIVE'`，与其他统计口径不一致。
- 风险2（P1）：维度发现仅采样 200 条（`_discover_dimension_codes`），可能漏维度。
- 风险3（P2）：问卷标签映射以单一 `(instrument_type, scale_level)` 推断，科目内混量表时存在错标风险。

---

## 业务价值

- 保证学校页展示“我校名次”“我校维度对标”严格以该校数据为口径。
- 保证问卷维度/题目分布严格以“本科目”数据计算，避免跨科目串扰。
- 保证区域/学校统计口径（ACTIVE 学校集）一致，减少前端与报告差异。
- 提升维度覆盖完整性与标签稳定性，减少重复返工。

---

## 目标与范围

- 目标：修复 P0/P1 问题；提供清晰验收口径与回归校验脚本；不改变对外 API 路径与 schema（仍为 v1.2）。
- 非目标：新增指标、支持 `interaction` 的完整计算逻辑（本期可选择性隐藏）。

---

## 用户故事

- 作为报表消费者，我希望学校页的统计与分布仅来源于该校数据，以便对比区域时口径一致。
- 作为 API 调用方，我希望问卷维度/题目分布仅包含本科目数据，避免混入其它问卷科目。
- 作为数据治理人员，我希望区域与学校统计均在 ACTIVE 学校集上统计，避免数据不一致。
- 作为开发者，我希望维度集合稳定且来源结构化表优先，减少“采样漏维度”的不确定性。

## 验收标准（可操作、可度量）

1) 问卷维度/题目选项分布按科目过滤（P0）
- REGIONAL：`subjects[].dimensions[].questions[].option_distribution[]` 与 `subjects[].dimensions[].option_distribution[]` 与 `subjects[].questions[]`，均仅来自 `subject_name=当前科目` 的 `questionnaire_option_distribution`/`question_dimension_mapping`。
- 验证 SQL（示例）：
  ```sql
  -- 维度-题目分布
  SELECT DISTINCT subject_name
  FROM questionnaire_option_distribution d
  JOIN question_dimension_mapping m ON m.batch_code=d.batch_code AND m.question_id=d.question_id
  WHERE d.batch_code=:batch AND d.subject_name=:subject AND m.subject_name=:subject;
  ```
  期望：仅返回 `:subject`。

2) 学校页增强统计使用学校级数据（P0）
- SCHOOL：`subjects[].(p10,p50,p90,discrimination,grade_distribution)` 来自该校数据；与区域级相同科目值允许不同。
- 验证：同一批次同一科目，对比 `/api/v12/batch/{batch}/regional` 与 `/api/v12/batch/{batch}/school/{school}`，学校页的 percentiles/grade 分布与区域不完全一致（除非极端全校=全域）。

3) 过滤或支撑 `interaction` 类型（P1）
- 本期选择：过滤（不出现在 `subjects`）。
- 验证：`subjects[].type` 仅为 `exam` 或 `questionnaire`。

4) 区域维度均分与 ACTIVE 学校口径对齐（P1）
- REGIONAL：维度均分统计限定 `school_master_data.status='ACTIVE'`，与学校排名/总校数口径一致。
- 验证 SQL：抽样维度代码，比较 `AVG` 前后学校集是否一致；并与 `total_schools` 对齐。

5) 维度集合完整（P1）
- 维度代码优先来源 `batch_dimension_definition`（若空，再回退 JSON 探测），确保与配置一致。
- 验证：`subjects[].dimensions[].code` 集合与 `SELECT dimension_code FROM batch_dimension_definition WHERE batch_code=:b AND subject_name=:s` 一致。

6) 精度统一（已具备，保底验收）
- 所有数值两位小数；百分比字段为 0–100 且 2dp。
- 验证：递归检查 JSON 中浮点数精度与百分比范围。

## 技术实现要点（给 DEV 的改造清单）

- A. 修复按维度→题目选项分布缺少科目过滤（P0）
  - 文件：`app/services/subjects_builder.py`
  - 函数：`_compute_questionnaire_dimension_question_option_distribution`
  - 要点：在 SQL WHERE 子句中同时限定 `qqd.subject_name = :subject` 且 `qdm.subject_name = :subject`；参数已存在 `:subject`。

- B. 学校页增强统计口径改为学校级（P0）
  - 文件：`app/api/subjects_v12_api.py`
  - 函数：`_fetch_v12_school`
  - 要点：
    - 现状：通过 `_fetch_student_scores(batch_code)` 获取全区域数据帧；应改为基于学校：`_fetch_school_scores(batch_code, school_code)`。
    - 两种实现：
      1) 使用 `calc_service._fetch_school_scores + _consolidate_multi_subject_results` 直接产出 per-subject 增强统计；
      2) 或调用 `calculate_school_statistics` 并将结果映射到 subjects（推荐代码一致化）。

- C. `list_subjects` 过滤 `interaction`（P1）
  - 文件：`app/services/subjects_builder.py`
  - 函数：`list_subjects`
  - 要点：在 SQL 或返回前过滤 `subject_type NOT IN ('interaction')`，或直接在 WHERE 增加 `scs.subject_type IN ('exam','questionnaire')`。

- D. 区域维度均分 JOIN ACTIVE 学校（P1）
  - 文件：`app/services/subjects_builder.py`
  - 函数：`_compute_regional_dimension_avgs`
  - 要点：无论走 JSON 维度路径还是问卷回退路径，均 JOIN `school_master_data` 且限定 `status='ACTIVE'`，与排名/总校数一致。

- E. 维度集合来源结构化表优先（P1）
  - 文件：`app/services/subjects_builder.py`
  - 函数：`_discover_dimension_codes`
  - 要点：优先查询 `batch_dimension_definition` 获取维度全集；若为空再回退 JSON 探测。

- F. 问卷标签映射健壮性（P2）
  - 文件：`app/services/subjects_builder.py`
  - 函数：`_get_scale_label_map`
  - 要点：当科目内存在多量表时，尽量按 `question_id` 粒度关联标签（如需最小改动，可保留现实现并在多量表检测到时记录警告日志）。

## 回归测试计划

- 接口级验证
  - `GET /api/v12/batch/{batch}/regional`
  - `GET /api/v12/batch/{batch}/school/{school}`
  - 验证 key points：
    - 学校页 p10/p50/p90/grade_distribution/discrimination 与区域不同（合理差异）。
    - REGIONAL 的 `dimensions[].questions[]/option_distribution[]` 与 `questions[]` 仅包含本科目数据。
    - `subjects[].type ∈ {exam, questionnaire}`。
    - `subjects[].school_rankings` 存在且排序正确；SCHOOL 有 `region_rank/total_schools`。
    - 两位小数精度与百分比范围合规。

- SQL 断言（建议准备 SQL 脚本）：
  - 核验 ACTIVE 学校口径一致：
    ```sql
    SELECT COUNT(DISTINCT school_id) FROM school_master_data WHERE batch_code=:b AND status='ACTIVE';
    ```
  - 核验维度集合：
    ```sql
    SELECT dimension_code FROM batch_dimension_definition WHERE batch_code=:b AND subject_name=:s;
    ```
  - 核验问卷分布科目过滤：见上文验收 SQL。

- 自动化/脚本（可选）
  - 复用 `test_aggregation_flow.py` 思路，新增断言：
    - 学校级与区域级相同科目百分位存在差异（或提示最小差距阈值）。
    - `subjects[].dimensions[].code` 与 BDD 一致。
    - 所有浮点均 `len(str(x).split('.')[-1]) <= 2`。

## 风险与回退

- 多量表问卷：若短期无法按题目级标签映射，保留现实现并记录警告，不阻断出数。
- 数据异构：若 BDD 维度不全，允许回退 JSON 探测并打印告警；验收允许“差异清单=空或仅白名单维度”。
- 性能：学校级增强统计改造需注意并发与缓存；如超时，可先按学校/科目逐科目计算并缓存。
