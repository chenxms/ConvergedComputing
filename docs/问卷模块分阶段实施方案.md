# 问卷模块分阶段实施方案（稳定性 → 规范化 → 性能化）

本文档面向 DEV/DBA/OPS，给出问卷链路的分阶段实施方案与操作手册，目标是在最小停机与可回滚前提下，先止血稳定，再进行数据模型规范化与性能优化。实施顺序建议遵循本文的阶段与里程碑。

---

## 0. 前置准备（所有阶段通用）

- 环境与备份
  - 确认测试/预发环境与生产环境的 MySQL 版本与参数一致（MySQL 8.x 推荐）。
  - 执行全量逻辑备份（mysqldump）与关键表热备（按业务窗口）：
    - student_cleaned_scores、questionnaire_question_scores、question_dimension_mapping、questionnaire_option_distribution、school_master_data、batch_dimension_definition、questionnaire_scale_options。
  - 预留回滚点：记录当前镜像标签、compose 文件、DDL 版本快照。
- 验收脚本基线（只读）：
  - 统计 NULL 标签：
    - `SELECT COUNT(*) FROM questionnaire_option_distribution WHERE (option_label IS NULL OR option_label='');`
  - 学校参与与样本数：
    - 统计问卷学校数、样本数、是否存在 0 样本学校进入分布写入。
  - 1267 错误复现与回归：挑选历史失败的 JOIN/过滤语句，用相同 SQL 验证。

## 阶段一｜最小化改动（1–2 周，停机=0/极短）

目标：不改表结构先止血，解决 1267 排序规则冲突、`option_label=null`，并提升关键查询可用性。

【实施记录｜2025-09-17】

- 查询级 COLLATE/CAST 统一（止血）
  - 在问卷相关服务中，对涉及批次/科目/学校等字符串的过滤统一使用 `utf8mb4_unicode_ci`，绑定参数一律 `CAST(... AS CHAR CHARACTER SET utf8mb4) COLLATE utf8mb4_unicode_ci`。
  - 修改范围：
    - app/services/question_option_distribution_service.py
      - get_school_option_distributions、get_regional_option_distributions 的过滤条件统一 COLLATE/CAST。
      - _calculate_school_option_distributions 明细查询的批次/科目/学校过滤统一 COLLATE/CAST。
      - _get_schools_for_processing 两分支均统一 COLLATE/CAST，并改为以问卷明细存在为准筛选学校（见下文“无问卷数据跳过”）。
      - populate_questionnaire_distributions 的批次过滤统一 COLLATE/CAST。
    - app/services/subjects_builder.py
      - _compute_school_rankings、_compute_school_region_rank 的批次/科目过滤统一 COLLATE/CAST。
      - _compute_questionnaire_question_option_distribution_school 的批次/科目/学校过滤统一 COLLATE/CAST。

- 输出端标签兜底（消灭 null）
  - 输出规则：优先“题目级量表映射” → 其次“科目级量表映射” → 最终兜底 `选项{level}`，确保接口与物化写入 `option_label` 非空。
  - 覆盖位置：
    - app/services/question_option_distribution_service.py: get_school_option_distributions、get_regional_option_distributions、_save_option_distributions。
    - app/services/subjects_builder.py: _compute_questionnaire_dimension_option_distribution、_compute_questionnaire_question_option_distribution、_compute_questionnaire_dimension_question_option_distribution、_compute_questionnaire_question_option_distribution_school。

- 历史数据一次性回填（数据修复）
  - 新增脚本 scripts/backfill_option_labels.py（支持 --batch，--subject 可选）。
  - 加强 QuestionOptionDistributionService.backfill_null_option_labels：
    - 增加题目级映射优先逻辑（基于 questionnaire_question_scores 推断每题主 instrument_type+scale_level 并从 questionnaire_scale_options 获取标签）。
    - 其后回退科目级映射，最后统一兜底 `选项{level}`；回填 SQL 条件统一 COLLATE/CAST。

- 关键复合索引（提升可用性）
  - 新增 Alembic 版本：alembic/versions/d1e2f3a4b5c6_add_questionnaire_stage1_indexes.py
  - 创建索引：
    - student_cleaned_scores: idx_scs_q (batch_code, subject_type, subject_name, school_code)
    - questionnaire_question_scores: idx_qqs_q (batch_code, subject_name, school_id, question_id)
    - questionnaire_option_distribution: idx_qod_reg (batch_code, subject_name, question_id, option_level)
    - questionnaire_option_distribution: idx_qod_school (batch_code, subject_name, school_id, question_id, option_level)
  - 说明：idx_qod_school 为覆盖查询的附加索引（与已存在的唯一索引列序不同），提升常见过滤顺序命中率。

- 学校“无问卷数据”跳过（契约明确）
  - _get_schools_for_processing 改为以 questionnaire_question_scores 是否存在记录为准（EXISTS/JOIN），样本为 0 的学校不进入填充与物化环节，避免“空壳”记录。

- 验收（自检）
  - 历史失败 SQL 回归通过，不再出现 1267 排序规则冲突。
  - 接口与物化输出中 option_label 均非空（缺失映射时按 `选项{level}` 兜底）。
  - `SELECT COUNT(*) FROM questionnaire_option_distribution WHERE (option_label IS NULL OR option_label='');` 返回 0。
  - 关键查询 EXPLAIN 命中新索引（idx_qqs_q、idx_qod_reg、idx_qod_school、idx_scs_q）。

### 1.1 查询级 COLLATE/CAST 统一（止血）

- 范围：所有问卷相关 SQL 的 JOIN/过滤比较键。
- 统一策略：左、右两侧及绑定参数一律 `utf8mb4_unicode_ci` 比较；参数使用 `CAST(:param AS CHAR CHARACTER SET utf8mb4) COLLATE utf8mb4_unicode_ci`。
- 重点文件与函数（逐条自查）：
  - `app/services/question_option_distribution_service.py`：
    - `_get_schools_for_processing`（两分支 JOIN/过滤）
    - 读取 `questionnaire_scale_options` / `questionnaire_question_scores` / `questionnaire_option_distribution` 的比较条件
  - `app/services/subjects_builder.py`：
    - 问卷区域维度分布、按题目分布、学校分布、维度均分计算、排名缓存等涉及 JOIN/过滤的 SQL

注：若某处已使用 COLLATE/CAST，请复核与以上规范一致；避免遗漏导致 1267。

### 1.2 输出端标签兜底（消灭 null）

- 约定：所有问卷选项分布输出（区域/学校/按维度/按题目）必须满足 `option_label` 非空；若无法从题目/科目量表映射得到，最终兜底写 `"选项{level}"`。
- 建议位置：
  - subjects 构建层：在从物化表读取或直接聚合时，最后一跳统一兜底。
  - 服务查询层：`QuestionOptionDistributionService.get_*` 读取时亦兜底，避免历史数据影响接口输出。

### 1.3 历史数据一次性回填（数据修复）

- 目标：将 `questionnaire_option_distribution` 中 `option_label IS NULL/''` 的历史记录回填为稳定标签。
- 推荐策略：
  1) 优先根据“题目量表映射/科目量表映射”获取标签；
  2) 若仍缺失，写入 `选项{level}`。
- 校验：
  - `SELECT COUNT(*) FROM questionnaire_option_distribution WHERE (option_label IS NULL OR option_label='');` 应返回 0。

### 1.4 关键复合索引（提升可用性）

MySQL 不支持带 WHERE 的部分索引；使用复合索引覆盖高频过滤：

```sql
-- 问卷数据定位与学校过滤
CREATE INDEX idx_scs_q ON student_cleaned_scores(batch_code, subject_type, subject_name, school_code);

-- 问卷明细聚合
CREATE INDEX idx_qqs_q ON questionnaire_question_scores(batch_code, subject_name, school_id, question_id);

-- 区域物化（题目维度）
CREATE INDEX idx_qod_reg ON questionnaire_option_distribution(batch_code, subject_name, question_id, option_level);

-- 学校物化（题目维度）
CREATE INDEX idx_qod_school ON questionnaire_option_distribution(batch_code, subject_name, school_id, question_id, option_level);
```

索引上线后，复核执行计划（EXPLAIN）命中情况。

### 1.5 学校“无问卷数据”跳过（契约明确）

- 定义：某校在某问卷科目 `student_count=0`，刷新/物化时跳过，不写入学校问卷科目；区域聚合仅按有数据学校汇总。
- 验收：区域结果不受无数据学校影响；学校层不产生空壳问卷科目。

### 阶段一验收（必过）

- 不再出现 1267 错误；历史失败 SQL 回归通过。
- 所有接口/物化输出中 `option_label` 非空（或已兜底）。
- `qod` 表内 `option_label` 无 NULL/空串。
- 关键查询 EXPLAIN 命中相应索引。

## 阶段二｜规范化重构（4–6 周，计划窗口）

目标：从模型与约束层面消除不确定性与运行时猜测，统一排序规则，固化“问卷事实”。

### 2.1 统一排序规则（库/表/列）

- 目标 collation（建议）：`utf8mb4_0900_ai_ci`（或团队既定标准）。
- 自查：
```sql
SELECT TABLE_SCHEMA, TABLE_NAME, TABLE_COLLATION
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME IN (
    'student_cleaned_scores','questionnaire_question_scores','question_dimension_mapping',
    'questionnaire_option_distribution','school_master_data','batch_dimension_definition','questionnaire_scale_options'
  );
```
- 执行（按表分批，窗口内）：
```sql
ALTER TABLE student_cleaned_scores CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE questionnaire_question_scores CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE question_dimension_mapping  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE questionnaire_option_distribution CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE school_master_data           CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE batch_dimension_definition   CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE questionnaire_scale_options  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

注意：大表转换会重建表与索引，需控制批次与时间窗口，监控复制延迟与锁等待。

### 2.2 引入“量表绑定事实表”（消灭运行时猜测）

```sql
CREATE TABLE questionnaire_scale_binding (
  batch_code     VARCHAR(50)  NOT NULL,
  subject_name   VARCHAR(100) NOT NULL,
  question_id    VARCHAR(50)  NOT NULL,
  instrument_type VARCHAR(50) NOT NULL,
  scale_level     INT         NOT NULL,
  is_reverse      TINYINT(1)  NOT NULL DEFAULT 0,
  PRIMARY KEY (batch_code, subject_name, question_id)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

- 初始化数据：
  - 从 `questionnaire_question_scores` 聚合出每个题目最常见的 `(instrument_type, scale_level, is_reverse)` 作为初始绑定；
  - 或从外部问卷配置导入，优先人工校对。
- 上线后：所有标签/等级推断一律优先走绑定表 + `questionnaire_scale_options`，减少“出现最多者”推断。

### 2.3 物化表约束与触发器（从数据层彻底消灭 NULL 标签）

建议区域行使用“哨兵学校”简化唯一性：`school_id='REGIONAL'`（而非 NULL）。

```sql
-- 约束（如历史数据存在 NULL 需先回填再加约束）
ALTER TABLE questionnaire_option_distribution
  MODIFY option_label VARCHAR(255) NOT NULL;

-- BEFORE INSERT 触发器（兜底回填）
DELIMITER $$
CREATE TRIGGER trg_qod_label_bi BEFORE INSERT ON questionnaire_option_distribution
FOR EACH ROW
BEGIN
  IF NEW.option_label IS NULL OR NEW.option_label='' THEN
    SET NEW.option_label = CONCAT('选项', NEW.option_level);
  END IF;
END$$
DELIMITER ;

-- BEFORE UPDATE 触发器（兜底回填）
DELIMITER $$
CREATE TRIGGER trg_qod_label_bu BEFORE UPDATE ON questionnaire_option_distribution
FOR EACH ROW
BEGIN
  IF NEW.option_label IS NULL OR NEW.option_label='' THEN
    SET NEW.option_label = CONCAT('选项', NEW.option_level);
  END IF;
END$$
DELIMITER ;

-- 唯一性（按学校/题目/等级，区域用 'REGIONAL'）
CREATE UNIQUE INDEX uk_qod_school_ql
ON questionnaire_option_distribution(batch_code, subject_name, school_id, question_id, option_level);
```

### 2.4 学校参与度白名单（可选但推荐）

```sql
CREATE TABLE questionnaire_school_participation (
  batch_code   VARCHAR(50) NOT NULL,
  subject_name VARCHAR(100) NOT NULL,
  school_id    VARCHAR(50) NOT NULL,
  participated TINYINT(1) NOT NULL DEFAULT 1,
  PRIMARY KEY (batch_code, subject_name, school_id)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

- 刷新/物化前先取参与学校集，彻底避免“无问卷学校”进入管道。

### 阶段二验收

- INFORMATION_SCHEMA 显示相关表已统一到目标 COLLATE。
- 绑定表生效：随机抽样若干题目与量表标签对齐。
- `qod` 表新增/更新记录均无 NULL 标签（触发器验证）。
- 区域行使用 `'REGIONAL'`，唯一索引无冲突。

## 阶段三｜性能优化与可观测（2–3 周，可滚动推进）

目标：在稳定与规范化基础上，进一步提升查询/物化性能与可观测性，降低维护成本。

### 3.1 数值型主键化（可按问卷链路先行试点）

- 为学校/科目/题目/批次引入 surrogate key（`school_pk/subject_pk/question_pk/batch_pk`）；
- 事实/物化表用数值键 JOIN，文本键退为维度属性；
- 迁移过程保留双写/双键过渡，完成后清理冗余索引与 COLLATE 依赖。

### 3.2 分区/分片与增量物化

- 分区建议：按 `batch_code`/日期范围进行 `RANGE COLUMNS(created_at)` 分区；
- 物化拆分：
  - `qod_school`（学校维度）与 `qod_regional`（区域聚合）分表；
  - 学校级增量刷新后触发区域再聚合（事件或定时任务）。

### 3.3 质量监控与契约测试

- 巡检脚本：
  - collation 差异扫描、`option_label` NULL/空串扫描、等级越界扫描；
  - 参与学校清单与实际写入差异扫描；
- 契约测试（CI 无网络环境可跑）：
  - 无 NULL 标签；
  - 区域聚合样本数 > 0；
  - 关键 SQL EXPLAIN 命中预期索引；
  - 学校 0 样本的问卷科目不写入。

## 回滚策略（各阶段通用）

- 代码层：回滚到上一个镜像/commit 标签；
- DDL 层：
  - COLLATE 统一：保留备份表，必要时回切；
  - 新表/索引/触发器：逐项 DROP；
  - 约束变更前务必完成数据回填，避免回滚时出现不一致；
- 数据层：通过备份与变更脚本的反向操作恢复；
- 验收失败即停止下一阶段推进。
