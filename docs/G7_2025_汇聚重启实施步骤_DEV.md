# G7-2025 汇聚重启实施步骤（DEV 执行版）

- 版本：v1.0（白名单-only 策略）
- 目标批次：G7-2025
- 适用对象：后端 DEV 工程师（本机/服务器一致执行）
- 关联文档：`G7_2025_PRODUCTION_EXECUTION_GUIDE.md`、`G7_2025_DEV_IMPLEMENTATION_SUMMARY.md`

---

## 1. 目标与策略
- 目标：在不放开全局写入的前提下，完成 G7-2025 新流程汇聚，并确保旧流程无法写入该批次。
- 策略：启用“增强守卫 + 白名单-only”。仅允许专用 DB 用户通过，其他来源全部阻断。本次白名单为 `chenlei%`。

---

## 2. 前置条件清单（必备）
- 专用数据库账号已建并授权（示例：`chenlei / lujing2022`）。关键权限：
  - `TRIGGER`、`CREATE` ON `appraisal_test`.*（安装触发器/配置表/白名单表）
  - `SELECT, INSERT, UPDATE, DELETE, CREATE`（涉及守卫/统计/校验相关表）
  - `PROCESS`（可选；便于 `SHOW PROCESSLIST`）
- 已暂停旧流程或确保旧流程不使用白名单用户（容器/定时任务/脚本）。
- 本地/服务器具备 Python 3.11+、能访问数据库网络。

---

  - `run_g7_pipeline_wrapper.py`（封装参数与日志）

- 一键执行
  - `scripts/run_g7_relaunch.sh`（Bash）

## 5. 手动执行（分步细化）

1) 设置连接变量（写入仅对 `chenlei%` 放行）
```bash
export PRODUCTION_DATABASE_URL='mysql+pymysql://chenlei:lujing2022@<host>:<port>/<db>?charset=utf8mb4'
```

2) 安装增强守卫 + 白名单-only
```bash
python scripts/enhanced_g7_guard.py install
python scripts/enhanced_g7_guard.py add-whitelist "chenlei%"
python scripts/enhanced_g7_guard.py disable-maintenance
python scripts/enhanced_g7_guard.py status
```
SQL 快检（可选）
```sql
SHOW TRIGGERS LIKE 'statistical_aggregations';
-- 期望存在 g7_enhanced_guard_insert / g7_enhanced_guard_update
```

3) 触发器快速校验
```bash
python scripts/validate_g7_triggers.py --quick
```

4) 预检与备份
```bash
python g7_precheck_suite.py --with-validation
```
备份 SQL 独立执行（可选）
```bash
mysql -u chenlei -p'lujing2022' -h <host> -P <port> <db> < backup_G7_2025_stats_clean.sql
```

5) 启动新流程（封装器）
```bash
python run_g7_pipeline_wrapper.py --batch G7-2025 --env production
```
并行监控（建议单独终端）：
```bash
python monitor_g7_pipeline.py --emergency-stop
```

6) 数据与 API 验证
```bash
python validate_g7_data.py --compare-backup
curl -s http://<host>:8000/api/v12/batch/G7-2025/regional | head -c 200
```

7) 收尾与持续防护
- 保持增强守卫有效；白名单仅保留 `chenlei%` 或专用流水用户。
- 一般不需开启“维护模式”；若必须，请通过 `g7_guard_switch.py maintenance on/off` 控制。

## 6. 白名单判定与安全说明（答疑）
- 判定逻辑：触发器内读取 `USER()`/`CURRENT_USER()`，在 `g7_guard_whitelist` 表中匹配 `user_pattern`（支持通配）。
- 本次配置：加入 `"chenlei%"`，即仅当会话用户以 `chenlei` 开头时，G7-2025 的 INSERT/UPDATE 会被放行；否则一律阻断并落库日志。
- 旧流程影响：只要旧流程不以 `chenlei` 账户连接，即便启动也无法对 G7-2025 写入（会被触发器拦截）。
- 运维配合：
  - 如已具备以上数据库权限与网络访问，DEV 可独立按本文档执行；
  - 推荐运维协助：确认无旧流程正在以 `chenlei` 身份运行；安排低峰执行窗口；若涉及安全基线或审计，配合留痕与回滚预案。

---

## 7. 常见问题与排查
- 守卫安装失败（缺 `TRIGGER/CREATE`）：请 DBA 确认 `GRANT TRIGGER, CREATE ON appraisal_test.*` 已生效。
- 仍有写入：检查连接使用用户是否为 `chenlei` 以外；查看 `g7_enhanced_guard_log.current_user_name` 溯源；必要时暂时开启维护模式完成补写。
- 备份 SQL 报错：使用 `backup_G7_2025_stats_clean.sql`（UTF-8 无 BOM），确认目标表存在且授权包含 `CREATE`。
- API 验证失败：先执行 `validate_g7_data.py --api-only` 定位，再看服务端日志查找异常栈。
