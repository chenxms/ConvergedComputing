# 部署快速核对清单（v1.2）

> 目的：降低“端口通，但 `/api/v12/*` 404/超时”的风险，确保 8000 对外提供 v1.2 路由。

---

## 1. 一键自检脚本

- 位置：`scripts/self_check_backend.py`
- 用法：

```bash
# 本机（服务器）执行
python scripts/self_check_backend.py --base http://127.0.0.1:8000 --batch G4-2025
# 可选学校级验证
python scripts/self_check_backend.py --base http://127.0.0.1:8000 --batch G4-2025 --school 5044
# JSON 输出
python scripts/self_check_backend.py --base http://127.0.0.1:8000 --batch G4-2025 --json
```

- 结果说明：
  - health/docs：200 视为 PASS
  - v12/regional：非 404/405 判定“路由存在”，200 则“可用”
  - database：调用部署包内数据库健康检查

> 若 v1.2 路由“存在但不可用”，多半为数据库不可达/数据未准备导致 500。

## 2. Docker Compose 关键项

- 文件：`deployment_package_production/docker/docker-compose.production.yml`
- 必查：
  - 端口映射：`ports: "${PORT:-8000}:8000"`，生产机若开放 8000 对外，则无需额外端口
  - 环境文件：`env_file: ../config/.env.production` 存在且内容正确（或使用 `DATABASE_URL` 一次性配置）
  - Redis：`REDIS_PASSWORD` 已设置强口令
  - 资源：根据机器规格调优 `cpus/memory`（避免 OOM 影响 Uvicorn）
  - 网络：默认 `bridge` 网络下，nginx 通过服务名 `app:8000` 访问应用
  - 可选 Nginx：使用 `--profile with-nginx` 启用 `nginx` 服务

- 常用命令：
```bash
# 启动（不带 nginx）
docker-compose -f deployment_package_production/docker/docker-compose.production.yml up -d --build
# 启动（带 nginx）
docker-compose -f deployment_package_production/docker/docker-compose.production.yml --profile with-nginx up -d --build
# 查看日志
docker-compose -f deployment_package_production/docker/docker-compose.production.yml logs -f app
# 验证端口
ss -lntp | grep :8000  # 或 lsof -i:8000
```

## 3. Nginx 反代核对

- 文件：`deployment_package_production/config/nginx.conf`
- 核心配置：
  - upstream 指向应用容器：`upstream converged_api { server app:8000; }`
  - API 统一前缀：
    ```nginx
    location /api/ {
      proxy_pass http://converged_api;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
      proxy_connect_timeout 60s;
      proxy_send_timeout 60s;
      proxy_read_timeout 60s;
    }
    ```
  - 文档与健康：`/docs`、`/redoc`、`/health` 均已转发
  - CORS（如有跨域）：按需在网关回显 `Access-Control-*` 头，并处理 `OPTIONS` 预检

- 验证：
```bash
# 80 端口代理路径
curl -i http://<域名或IP>/health
curl -i "http://<域名或IP>/api/v12/batch/G4-2025/regional"
```

> 若 80 正常、8000 异常，说明只开放了 80；请通过 Nginx 访问 `/api/*`。

## 4. 应用路由与服务

- 应用挂载（FastAPI）：`deployment_package_production/app/main.py`
  - `app.include_router(subjects_v12_router, prefix="/api/v12")`
  - `uvicorn.run(..., port=8000)`
- 关键路由文件：`deployment_package_production/app/api/subjects_v12_api.py`
  - 区域级：`GET /api/v12/batch/{batch_code}/regional`
  - 学校级：`GET /api/v12/batch/{batch_code}/school/{school_id}`
  - 物化：`POST /api/v12/batch/{batch_code}/materialize`

## 5. 常见问题与定位

- 现象：8000 可连但 `/api/v12/*` 404
  - 原因：部署了旧镜像/旧代码（未包含 v1.2 路由）或 Nginx 未转发到应用
  - 处置：重新构建并启动，核对 `main.py` 是否挂载 `/api/v12`

- 现象：`/api/v12/*` 返回 500
  - 原因：数据库不可达/无数据/超时
  - 处置：运行自检脚本查看 `database`，检查 `.env.production` 与安全组/白名单

- 现象：`/docs` 403/401
  - 原因：网关策略或鉴权
  - 处置：以 `/health` 与 `/api/v12/*` 为联调依据，`/docs` 非必需

---

## 6. 变更建议

- 前后端统一使用 `/api/v12`（不要使用 `/api/v1.2`）
- 对外仅开放 8000 或通过 80 反代 `/api/*` 到应用 8000
- 初次部署后执行自检脚本，纳入运维 SOP
