# 数据质量监控使用指南

## 概述

本指南介绍如何使用新建立的数据质量验证和监控机制，确保后续批次（G7、G8及未来批次）的数据质量，防止类似G4数据问题再次发生。

## 系统架构

### 核心组件

1. **数据治理配置系统** (`scripts/data_governance_config.py`)
   - 定义数据质量规则和检查标准
   - 配置处理阶段和依赖关系
   - 管理预警阈值和处理策略

2. **数据质量服务** (`app/services/data_quality_service.py`)
   - 提供统一的质量检查接口
   - 集成到现有处理流程中
   - 支持实时监控和预警

3. **专用验证工具**
   - `scripts/data_quality_monitor.py` - 全面的数据质量监控
   - `scripts/school_data_validator.py` - 专门的学校数据验证
   - `app/utils/data_validation.py` - 增强版基础验证器

## 快速开始

### 1. 生成数据治理配置

首先生成默认的数据治理配置文件：

```bash
cd D:\myproject\后端\ConvergedComputing
python scripts\data_governance_config.py --generate --config-file config\data_governance.json
```

### 2. 验证配置有效性

```bash
python scripts\data_governance_config.py --validate --config-file config\data_governance.json --show-order
```

### 3. 运行批次质量检查

对新的批次（如G7-2025）运行全面质量检查：

```bash
# 全面监控检查
python scripts\data_quality_monitor.py G7-2025 --save-report --verbose

# 学校数据专项验证
python scripts\school_data_validator.py G7-2025 --save-report --generate-fix-script

# 集成服务检查
python app\services\data_quality_service.py G7-2025 ALL
```

## 详细使用说明

### 数据质量监控工具 (data_quality_monitor.py)

这是最全面的监控工具，提供8个维度的质量检查：

#### 基本使用

```bash
# 基础检查
python scripts\data_quality_monitor.py G7-2025

# 详细检查并保存报告
python scripts\data_quality_monitor.py G7-2025 --save-report --verbose
```

#### 检查内容

1. **基础数据存在性检查** - 确保必要的表有数据
2. **学校数据一致性检查** - 验证school_master_data的权威性
3. **学校名称完整性检查** - 防止NULL学校名称问题
4. **数据源统一性检查** - 确保数据来源一致
5. **学生数据分布检查** - 分析数据分布合理性
6. **历史数据对比检查** - 与历史批次对比
7. **数据完整性检查** - 验证字段完整性
8. **性能影响预估** - 评估处理资源需求

#### 输出示例


### 学校数据验证器 (school_data_validator.py)

专门针对学校数据的深度验证工具：

#### 基本使用


#### 检查内容

- **学校ID格式验证** - 确保4位数字格式
- **学校名称标准化** - 验证名称规范
- **跨表一致性验证** - 检查表间数据一致性
- **数据源统一性** - 确保来源统一
- **学校状态验证** - 检查状态字段
- **孤立学校检测** - 发现数据孤岛
- **重复学校检查** - 识别重复记录

### 数据质量服务 (DataQualityService)

集成到处理流程中的质量检查服务：

## 集成到现有流程

### 1. 批次管理API集成

在批次开始处理前，添加质量检查：

```python
from app.services.data_quality_service import check_batch_ready_for_processing

@router.post("/batches/{batch_code}/start-processing")
async def start_batch_processing(batch_code: str, db: Session = Depends(get_db)):
    # 处理前质量检查
    quality_check = check_batch_ready_for_processing(db, batch_code)
    
    if not quality_check['can_proceed']:
        return {
            "status": "blocked",
            "message": "质量检查失败，无法开始处理",
            "issues": quality_check['blocking_issues']
        }
    
    # 继续正常处理流程
    # ...
```

### 2. 数据清洗流程集成

在数据清洗前后添加检查：

```python
from app.services.data_quality_service import (
    check_batch_ready_for_cleaning,
    check_batch_aggregation_quality
)

def clean_batch_data(batch_code: str, db_session: Session):
    # 清洗前检查
    pre_clean_check = check_batch_ready_for_cleaning(db_session, batch_code)
    if not pre_clean_check['can_proceed']:
        raise ValueError(f"数据不适合清洗: {pre_clean_check['blocking_issues']}")
    
    # 执行清洗
    # ... 清洗逻辑
    
    # 清洗后检查
    post_clean_check = check_batch_aggregation_quality(db_session, batch_code)
    if not post_clean_check['can_proceed']:
        logger.warning(f"清洗结果有问题: {post_clean_check['warnings']}")
```

### 3. 实时监控集成

在长时间运行的任务中添加进度监控：

```python
from app.utils.data_validation import DataValidator

def long_running_batch_process(batch_code: str, db_session: Session):
    validator = DataValidator(db_session)
    
    # 定期检查进度
    while processing:
        progress = validator.monitor_batch_progress(batch_code)
        
        # 检查是否有处理停滞
        for issue in progress.get('issues_detected', []):
            if issue['type'] == 'PROCESSING_STALLED':
                logger.warning(f"处理停滞: {issue['message']}")
                # 可以触发重试或报警
        
        time.sleep(60)  # 每分钟检查一次
```

## 配置管理

### 质量规则配置

数据治理配置文件定义了以下关键规则：

#### 关键规则（零容忍）

- **NULL_SCHOOL_NAMES** - NULL学校名称检查
- **ORPHANED_SCHOOLS** - 孤立学校检查
- **POST_PROCESSING_NULL_NAMES** - 处理后NULL名称检查

#### 高级规则

- **INVALID_SCHOOL_ID_FORMAT** - 学校ID格式检查
- **AGGREGATION_COMPLETENESS** - 汇聚完整性检查
- **INVALID_JSON_FORMAT** - JSON格式验证

#### 中级规则

- **SCHOOL_COUNT_DEVIATION** - 学校数量偏差检查
- **LOW_STUDENT_SCHOOLS** - 学生数据分布检查
- **NAME_INCONSISTENCY** - 跨表名称一致性检查

### 阈值调整

可以通过修改配置文件调整质量阈值：

```json
{
  "global_settings": {
    "school_id_range": [5044, 5099],
    "min_student_per_school": 10,
    "max_school_count_deviation_percent": 5.0,
    "min_data_completeness_rate": 95.0
  }
}
```

## 预警机制

### 自动预警

系统会在发现关键问题时自动发出预警：

1. **关键问题阻断** - 立即停止处理并发出警报
2. **质量下降警告** - 数据质量趋势下降时预警
3. **异常检测** - 检测到异常数据模式时报告

### 预警配置

可以在配置文件中设置预警参数：

```json
{
  "alert_settings": {
    "log_level": "INFO",
    "alert_threshold": "HIGH",
    "notification_cooldown_minutes": 60
  }
}
```

## 最佳实践

### 1. 处理前必检清单

每个新批次处理前必须执行：

```bash
# 1. 生成或更新治理配置
python scripts\data_governance_config.py --generate

# 2. 全面质量检查
python scripts\data_quality_monitor.py [BATCH_CODE] --save-report

# 3. 学校数据专项验证  
python scripts\school_data_validator.py [BATCH_CODE] --save-report

# 4. 确认无阻断问题
python app\services\data_quality_service.py [BATCH_CODE] DATA_PREPARATION
```

### 2. 质量问题处理流程

发现质量问题时的标准处理流程：

1. **立即停止处理** - 如果有关键问题
2. **分析问题根因** - 检查数据源和处理逻辑
3. **执行修复操作** - 使用生成的修复脚本或手动修复
4. **重新验证** - 修复后重新运行质量检查
5. **记录问题和解决方案** - 更新知识库

### 3. 定期维护

建议定期执行：

- **每周** - 检查和更新质量规则配置
- **每月** - 生成质量趋势报告
- **每季度** - 评估和优化检查规则

### 4. 性能优化

为避免影响处理性能：

- 在低峰时段运行全面检查
- 对大批次使用分段检查
- 监控检查执行时间，优化慢查询
