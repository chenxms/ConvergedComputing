# V12增强汇聚修复行动计划

## 背景与目标
- 当前 app/services/subjects_builder.py 在强制增强改造后，输出结构偏离既有 V12 规范（等级占比误写入 metrics、缺失 percentiles、维度列表为空等）。
- 目标：在不回退至 V10 的前提下，恢复原有 V12 字段布局与取值方式，同时保留清洗阶段预计算的性能优化，确保所有批次的区域/学校汇聚结果与历史输出一致。

## 参考基线
- 旧版稳定实现：deployment_package_production/app/services/subjects_builder.py 及 deployment_package_production/app/services/calculation_service.py。
- 数据仓储契约：deployment_package_production/docs/stories/汇聚指标修复_改动清单_v1.2.md 中的字段清单。

## 实施步骤
1. 差异对比
   - 对比当前 app/services/subjects_builder.py 与基线文件，梳理科目结构差异（metrics、dimensions、school_rankings、问卷题目输出）。
   - 记录所有字段偏差，形成修复清单。
2. 恢复科目指标结构
   - 重写 _compute_subject_metrics：确保返回值包含 avg/stddev/max/min/subject_full_score/student_count/score_rate/percentiles/discrimination。
   - 将 grade_distribution 回置到科目顶层，保留 rate_excellent 等派生指标仅用于校验。
   - 指标值仍优先取自预计算表，保持性能优化。
3. 维度与题目数据补齐
   - 恢复维度列表生成逻辑：dimensions 中写入 avg 与 score_rate，必要时从增强统计或预计算缓存补齐。
   - 区域 subjects 恢复 questions 列表；学校 subjects 使用 _compute_questionnaire_question_option_distribution_school 输出题目占比。
4. 学校排名结构复原
   - _compute_school_rankings 仅保留 school_id、school_name、avg、score_rate、rank、total_schools，与原 V12 输出一致。
   - 移除新增的 stddev/difficulty 等冗余字段。
5. 验证逻辑调整
   - 更新 CalculationService._validate_enhanced_subjects 按 V12 契约校验：
     - 非问卷科目强制存在 percentiles、discrimination、grade_distribution。
     - 问卷科目强制存在 dimensions 与 questions。
     - metrics 必须含 avg/stddev/max/min/subject_full_score/student_count/score_rate。
6. 回归测试
   - 运行 python run_full_batch_pipeline.py <批次>（建议 G4-2025、G8-2025）核对区域与学校 JSON。
   - 对比历史样例：docs/G4-2025区域汇聚数据样本.txt、subjects_enhanced_test_result.json。
   - 执行 poetry run pytest -k subjects_builder 验证单元测试；必要时补充快照测试。
7. 文档更新
   - 在 docs/G4-2025增强汇聚实施手册.md、docs/批次全流程增强汇聚实施方案.md 中同步记录恢复细节、测试结果与耗时。

## 验收标准
- 区域/学校 subjects JSON 与历史 V12 产出字段一致（含 percentiles、grade_distribution、dimensions.score_rate、questions）。
- statistical_aggregations statistics_data 中无等级占比落在 metrics 的情况。
- 清洗阶段预聚合仍可用，整体汇聚耗时不劣于改造前。
